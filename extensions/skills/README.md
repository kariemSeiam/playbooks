# Skills — an agent extension's auto-loading law

`SKILL.md`: the mechanism, why it already travels across every harness
this operator runs (not just Claude Code), the open ecosystem around it,
and when a plain playbook note earns real promotion into one.

## Files in this playbook

- [mechanism.md](mechanism.md) — what a Skill actually is (frontmatter/body split,
  the cross-harness proof already running in this operator's own setup),
  and where one lives on disk, per harness and per scope.
- [ecosystem.md](ecosystem.md) — the open registries worth knowing (skills.sh,
  ClawHub, Hermes), and how to use one before building from scratch.
- [promotion-and-authoring.md](promotion-and-authoring.md) — the rule for when a playbook note
  becomes a Skill, and the convention this vault follows when it builds
  one.

## Related

- **`../mcp/`** — the capability-layer counterpart; a Skill teaches, an
  MCP server does.
- **`../plugins/`** — the bundling layer a Skill can ship inside of,
  without being defined by it.
- [for-agents.md](../../language/markdown/for-agents.md) — the tiered-loading theory
  a Skill's frontmatter/body split is one implementation of.

## The one rule that overrides all of this

A project's own stated convention always wins over this playbook's
defaults — same as every other playbook here.
